## Требования

### T1. Элемент управления на карточке
На каждой карточке есть элемент управления (чекбокс), который переключает признак «выполнено».
**Сценарий проверки:** пользователь кликает по чекбоксу невыполненной карточки → карточка визуально становится приглушённой и зачёркнутой. Повторный клик возвращает обычный вид. (Проверка: да/нет, взглядом).

### T2. Сохранение состояния на сервере
После обновления страницы состояние карточки не теряется.
**Сценарий проверки:** отметить карточку выполненной → нажать F5 → карточка остаётся приглушённой и зачёркнутой. (Проверка: да/нет).

### T3. Отдельный эндпоинт для изменения
Сервер принимает изменение статуса по адресу, адресованному конкретной карточке, отдельным запросом.
**Сценарий проверки:** отправка запроса на изменение статуса конкретной карточки успешно обновляет только эту карточку, не затрагивая другие. (Проверка: да/нет, через вкладку Network или curl).

### T4. Валидация данных (400 Bad Request)
Если в запросе передано негодное значение отметки (не boolean), сервер отклоняет запрос кодом 400. Проверка выполняется в промежуточной функции, контроллер об этой проверке не знает.
**Сценарий проверки:** отправка запроса с телом `{"isDone": "yes"}` или без поля `isDone` возвращает статус 400. (Проверка: да/нет).

### T5. Обработка несуществующей карточки (404 Not Found)
Попытка изменить статус несуществующей карточки возвращает код 404. Решение о коде 404 принимает контроллер; сервис лишь сообщает, что карточка не найдена.
**Сценарий проверки:** отправка запроса на изменение карточки с несуществующим ID возвращает статус 404. (Проверка: да/нет).

### T6. Соблюдение границы слоёв на сервере
В файле сервиса отсутствуют слова `req`, `res` и `status`. Сервис не знает про HTTP.
**Сценарий проверки:** поиск по файлу сервиса не находит указанных слов. (Проверка: да/нет, Ctrl+F).

### T7. Структура слоёв
Новый код разложен по существующим слоям: строка в роутере, функция в контроллере, функция в сервисе. Точные пути в роутере стоят выше параметрических (если таковые есть).
**Сценарий проверки:** код организован в файлах `routes`, `controllers`, `services` без дублирования логики. (Проверка: да/нет).
